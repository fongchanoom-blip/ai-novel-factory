# 友好错误信息协议（Friendly Error Messages）

[REF:protocol.friendly_errors]

## 一、设计哲学

**核心原则**：**"每个错误都是一个教学机会"**

技术用户习惯了技术错误信息，但小白用户看到 `FAIL: missing ID:xxx` 会直接放弃。

**为什么需要友好错误信息？**
- 错误是用户最容易流失的地方
- 友好的错误信息 = 教学机会
- "怎么办"比"是什么错"更重要

**核心策略**：
- ❌ **不要**使用技术术语
- ❌ **不要**只说"错了"
- ✅ **说清楚**发生了什么
- ✅ **告诉用户**怎么办
- ✅ **保持鼓励**语气

## 二、技术风 vs 大白话对照表

### 2.1 知识库相关错误

| ❌ 技术风 | ✅ 大白话 |
|----------|-----------|
| `FAIL: missing ID:protocol.knowledge_base_contract` | 📝 嘿！我注意到你还没告诉我一些基本信息。别担心，我可以用通用默认。 |
| `FAIL: knowledge_base_contract.ABILITY_DEGRADATION` | 🤔 你想做的功能需要更多设定，但你还没准备好。要不要先用默认？ |
| `ERROR: 缺少世界基石.md` | 📚 我还没建好你的项目档案。我可以现在帮你建立吗？ |
| `ERROR: 缺少世界观规则.md` | 🌍 你还没告诉我你的世界规则（比如等级体系）。我可以先用通用仙侠规则。 |

### 2.2 协议相关错误

| ❌ 技术风 | ✅ 大白话 |
|----------|-----------|
| `arbitration conflict` | 🤔 AI 在纠结两个指令，让我帮你决定。 |
| `circular dependency detected` | 🔄 系统发现循环依赖，让我自动修复。 |
| `protocol load failed` | ⚠️ 这个功能暂时不可用，让我换一个方法。 |

### 2.3 一致性错误

| ❌ 技术风 | ✅ 大白话 |
|----------|-----------|
| `fact_lock violation` | ⚠️ 等等！这个跟你前面写的不一致。让我帮你修正。 |
| `consistency check failed` | 🔍 我发现这一章跟你前面的设定有点冲突。要不要我改一下？ |
| `timeline conflict` | ⏰ 时间线有点问题，让我调整一下。 |

### 2.4 模型相关错误

| ❌ 技术风 | ✅ 大白话 |
|----------|-----------|
| `LLM API error` | 📡 网络有点卡，让我重连... |
| `rate limit exceeded` | ⏱️ AI 这会儿有点忙，让我等一下再试... |
| `token limit exceeded` | 📝 内容有点长，让我精简一下... |
| `model timeout` | 😴 AI 睡着了，让我叫醒它... |

### 2.5 用户输入错误

| ❌ 技术风 | ✅ 大白话 |
|----------|-----------|
| `invalid input format` | 🤔 你说的我有点不太明白。能不能换个说法？ |
| `unknown trigger` | 🤷 我没听懂你要做什么。你可以说 "试试看" / "继续写" / "卡文了" / "查看进度" |
| `empty input` | 📝 你好像什么都没说？告诉我你想做什么吧！ |

## 三、错误信息模板

### 3.1 模板 1：缺失资源

```
[emoji] [发生了什么 — 大白话]
[怎么办 — 给选项]
```

**示例**：

```
📝 嘿！我注意到你还没告诉我你的写作风格。

别担心，我可以先按「通用风格」帮你写，
但你可能觉得不太像你。

你想怎么做？

【A】给我看看你喜欢的段落（30 秒）
    → 你只需要复制 2-3 段你最喜欢的描写，我就能学会你的风格

【B】先用通用风格写（10 秒）
    → 我用通用风格写，你看看喜不喜欢再决定

【C】让我帮你选一个风格模板
    → 我推荐几种常见风格（如"古风仙侠""现代都市""轻松搞笑"）

输入 A、B 或 C 继续 ✍️
```

### 3.2 模板 2：操作失败

```
[emoji] [操作失败 — 大白话 + 不责怪]
[原因 — 简单解释]
[怎么办 — 给选项]
```

**示例**：

```
😅 哎呀，AI 这会儿没灵感，让我重新试试...

（10 秒后重试）

或者你想：
【A】换个方向试试
【B】调整一下你的输入
【C】稍后再试
```

### 3.3 模板 3：网络/系统错误

```
[emoji] [系统问题 — 不让用户担心]
[自动处理 — 重试/降级]
[怎么办 — 给选项]
```

**示例**：

```
📡 网络有点卡，我正在自动重连...

[尝试 1 次]
[尝试 2 次]
[尝试 3 次]

✅ 好了！继续。

（如果失败）

⏱️ AI 这会儿有点忙，稍后再试？
```

### 3.4 模板 4：用户操作不当

```
[emoji] [操作不当 — 不指责]
[正确做法 — 示例]
```

**示例**：

```
🤔 你说「继续写」但我找不到你的项目。

可能是：
1. 你还没建项目（先 /novel:new）
2. 项目目录不对（告诉我你的项目在哪）
3. 数据丢失（从备份恢复）

或者你想：
【A】先建个项目 /novel:new
【B】切换到其他项目
【C】查看我的项目 /novel:list
```

## 四、错误恢复流程

### 4.1 一般流程

```
发生错误
   ↓
捕获错误
   ↓
转化为友好信息（基于本协议）
   ↓
自动尝试恢复（1-3 次）
   ↓
如果还是失败 → 给用户选项
```

### 4.2 关键原则

```yaml
原则 1: 不责怪用户
原则 2: 不显示技术细节
原则 3: 提供明确的"下一步"
原则 4: 保持鼓励语气
原则 5: emoji + 友好文字
原则 6: 即使失败也要感谢用户
```

## 五、用户输入错误的特殊处理

### 5.1 用户输入太模糊

```
🤔 你说的「写小说」我有点不太明白。

你的意思是：
1. 我想做一本新小说 → /novel:new
2. 继续写我已有的 → /novel:continue
3. 给我看看你能写什么 → /novel:demo
4. 卡文了 → /novel:stuck

或者直接告诉我更多 ✍️
```

### 5.2 用户输入不符合触发词

```
🤔 我没听懂「[用户输入]」。

但我可以尝试理解！以下是我能做的：

🚪 入口
- /novel:demo（30 秒体验）
- /novel:quick（快速试写）
- /novel:new（开始新小说）
- /novel:continue（继续写）

💡 辅助
- /novel:stuck（卡文急救）
- /novel:daily（日更管理）
- /novel:cowrite（AI 共写）
- /novel:fix（优化修改）

🚀 发布
- /novel:submit（投稿分析）

或者直接告诉我你想做什么 ✍️
```

### 5.3 用户表达不清

```
😊 我不确定我理解对了。让我猜一下：

你想要的是：[AI 的猜测]

如果对了，请说 "对"。
如果不对，请更具体地告诉我 ✍️
```

## 七、避免的错误模式

### 7.1 ❌ 绝对不要

```
❌ "Error: invalid argument"
❌ "Exception in thread..."
❌ "500 Internal Server Error"
❌ "权限不足"
❌ "参数错误"
❌ "未授权"
❌ "操作失败"
❌ "失败"
```

### 7.2 ✅ 推荐使用

```
✅ "AI 还没准备好，让我帮你..."
✅ "网络有点卡..."
✅ "你想..."
✅ "我建议你..."
✅ "完成！[庆祝]"
✅ "🤔 [emoji] + 大白话"
```

## 九、与其他协议的协同

### 9.1 错误信息 vs 知识库契约

```
当知识库缺失时：
   ↓
触发 protocol.knowledge_base_contract
   ↓
但不要显示技术错误
   ↓
用本协议的友好模板
```

### 9.2 错误信息 vs 仲裁

```
当用户指令冲突时：
   ↓
触发 protocol.arbitration
   ↓
不要显示 "arbitration conflict"
   ↓
用 "AI 在纠结两个指令，让我帮你决定"
```
