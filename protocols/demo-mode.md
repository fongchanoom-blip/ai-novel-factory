# 30 秒体验模式协议（Demo Mode）

[REF:protocol.demo_mode]

## 一、设计哲学

**核心原则**：**"30 秒内让用户知道 Auto-Novel 能做什么"**

这是 Auto-Novel 最重要的入口——用户的第一体验决定他们是否继续使用。

**为什么是 30 秒？**
- GitHub README 平均浏览时间：5-10 秒
- 用户决定"是否值得深入"的时间：30 秒
- 30 秒后还在看 = 高意向用户

**核心策略**：
- ❌ **不要**问用户任何问题（不问类型、不问主角、不问灵感）
- ❌ **不要**要求任何准备（不要知识库、不要大纲）
- ❌ **不要**解释复杂概念（不解释协议、评分、上下文）
- ✅ **直接生成**一个 500 字的高质量试稿
- ✅ **立即展示**AI 的 5 大能力
- ✅ **明确引导**"下一步该做什么"

---

## 二、触发词

```
用户说：
- "/novel:demo"
- "试试看"
- "demo"
- "看看你能做什么"
- "show me"
```

**特别说明**：Demo 模式**不需要任何参数**，用户说什么都是生成同一个 demo（除非用户指定题材）。

## 三、完整流程（30 秒）

### 3.1 立即输出（0 秒）

**第 1 段：欢迎 + 展示**

```
🎬 30 秒体验 Auto-Novel

让我立刻给你展示我能写什么！
正在生成试稿...
```

**第 2 段：500 字试稿**（约 15-20 秒）

> 📖 第一章 入门测试
>
> 我站在青云宗的山门前，望着云雾缭绕的宗门大殿。
>
> 这是我第三次来到这座宗门了。前两次，我被拒之门外，原因很简单——资质不够。
>
> 但这一次不同。
>
> "张三是吧？"主考官低头扫了一眼我的命牌，"乙等下品，不建议入门。"
>
> 我没有说话。我知道自己的资质——
>
> 在这个以灵根定命运的世界里，乙等下品意味着永远的外门弟子，永远的杂役，永远的底层。
>
> 但我手里，握着一张皱巴巴的符箓。
>
> 这是我在山门外捡到的，没人要的东西。但我能感觉到——
> 里面有一股不属于这个世界的气息。
>
> "还有要考核的吗？"主考官不耐烦地问。
>
> "有。"
>
> 我迈步上前，拱手行礼："弟子张三，请考官考核。"
>
> 主考官叹了口气，像是看一个不自量力的傻瓜。
>
> 我不怪他。任何人看到乙等下品的资质，都不会相信我能通过考核。
>
> 但他们不知道的是——
>
> 昨夜，我用那张符箓，看到了命牌上隐藏的一个字。
>
> 那是我原本灵根的名字。
>
> ——天。
>
> 我深吸一口气。
>
> 这一刻，不是入门测试。
>
> 是命运改写的开始。

**第 3 段：能力展示**（约 5 秒）

```
💡 这就是 Auto-Novel 的能力：

✅ 古风文风稳定（不是现代网感）
✅ 主角人设清晰（张三：乙等下品 + 神秘符箓）
✅ 章节钩子强（"天"字悬念 + 命运改写）
✅ 世界观设定完整（灵根等级 + 宗门等级）
✅ 自动铺垫伏笔（符箓 + 神秘命牌）

完整生成这一章只要 30 秒 ✨
```

**第 4 段：引导下一步**（约 5 秒）

```
🎯 接下来你要做什么？

A. /novel:quick "你的故事灵感"
   → 让我按你的想法写（30 秒）

B. /novel:new
   → 正式开始一部长篇小说（3 分钟引导）

C. /novel:help
   → 看看我还能做什么

输入 A、B 或 C ✍️
```

### 3.2 完整时间分配

```
0 秒：   🎬 欢迎 + 正在生成
0-20 秒：500 字试稿生成
20-25 秒：能力展示
25-30 秒：引导下一步
```

**总耗时**：30 秒（其中生成耗时 ~20 秒）

## 四、文风与题材默认设置

### 4.1 默认试稿配置

```yaml
demo_default:
  题材: 玄幻 / 仙侠
  视角: 第一人称（"我"）
  基调: 热血 / 阴谋
  章节: 第 1 章 入门测试
  目标字数: 500 字
  文风: 古风仙侠，略带悬疑
  钩子: 神秘符箓 + 命运悬念
```

### 4.2 用户指定题材

```bash
/novel:demo 都市       # 都市题材试稿
/novel:demo 言情       # 言情题材试稿
/novel:demo 悬疑       # 悬疑题材试稿
/novel:demo 科幻       # 科幻题材试稿
```

**支持题材**：玄幻、仙侠、都市、言情、悬疑、科幻、历史、军事、其他

## 五、试稿选择的考量

### 5.1 为什么选玄幻仙侠？

- ✅ **最有网文代表性**（玄幻占网文 60%+ 市场）
- ✅ **金手指设定容易展示**（透视符箓等经典套路）
- ✅ **古风文风对比鲜明**（避免被误认现代网感）
- ✅ **章节钩子自然**（悬念 + 战斗 + 升级）
- ✅ **AI 表现力强**（世界观容易构建）

### 5.2 为什么 500 字？

- ✅ **30 秒内可读完**（约 200 字/分钟 × 2.5 分钟 = 600 字，考虑到快速浏览 500 字）
- ✅ **足以展示文风 + 设定 + 钩子**
- ✅ **不让用户等待太久**
- ✅ **如果用户要更多，给出快速试写入口**

## 六、能力展示的 5 个维度

每次 demo 必须展示 5 大能力（让用户知道 Auto-Novel 强在哪里）：

| 维度 | 展示内容 | 让用户知道 |
|------|----------|-----------|
| **1. 文风** | "古风仙侠，略带悬疑" | 我能稳定文风 |
| **2. 设定** | "灵根等级 + 宗门等级" | 我能构建世界观 |
| **3. 人设** | "张三：乙等下品 + 神秘符箓" | 我能塑造角色 |
| **4. 钩子** | "神秘符箓 + '天'字悬念" | 我懂网文套路 |
| **5. 伏笔** | "符箓 + 神秘命牌 + 暗线" | 我能自动铺垫 |

## 七、错误处理（人性化的错误信息）

### 7.1 如果 LLM 调用失败

```
😅 哎呀，AI 这会儿有点紧张，让我重新试试...

（10 秒后重试）
```

### 7.2 如果用户指定了未知题材

```
🤔 你说的「[题材]」我不太熟悉，但我可以试试看。

让我用通用网文风格写一段 500 字，你看看喜不喜欢：

（生成通用风格的试稿）
```

### 7.3 如果网络问题

```
📡 网络有点卡，让我重连...

（自动重试 3 次）
```

### 7.4 不允许的请求

❌ 不要让用户指定主角名字（demo 是固定的）
❌ 不要让用户修改 demo 内容（用户要看的是 AI 的能力，不是他的想法）
❌ 不要让 demo 进入长篇创作（这只是体验入口）

如果用户想深入 → 引导到 `/novel:quick`
