# AI 共写协议（Cowrite Mode）

[REF:protocol.cowrite]

## 一、设计哲学

**核心原则**：**"你一句我一句，AI 帮你接续"**

很多创作者实际想要的不是"AI 自动写"，而是"AI 帮我接"——保留创作主导权，AI 处理繁琐的扩写。

**为什么需要 AI 共写？**
- 全自动写作 = AI 主导，可能与作者想法不同
- 纯手写 = 太慢，效率低
- 共写 = 作者主导 + AI 加速，最佳平衡

**核心策略**：
- ✅ **作者写开头，AI 接续**（每次 1-3 句）
- ✅ **AI 提供 3 个版本供选择**
- ✅ **作者可随时修改 AI 输出**
- ✅ **支持多种协作模式**

## 三、协作模式

### 3.1 模式 A：接续模式（默认）

**流程**：
1. 作者写 1-3 句
2. AI 接续 3 个版本（每个版本 1-3 句）
3. 作者选择或继续

```
👤 我深吸一口气，抬手推开那扇破旧的木门。

🤖 AI 提供了 3 个接续版本：

【版本 1：悬念】
门后是一片漆黑，隐约传来低沉的咆哮。
我没有退路，径直踏入。

【版本 2：动作】
门后陡然一阵寒风扑面，我手中剑已出鞘。

【版本 3：心理】
门后是什么？答案就在其中。我等了三年。

你选哪个？
A. 1
B. 2
C. 3
D. 都不要，我自己写（继续）
```

### 3.2 模式 B：扩写模式

**流程**：
1. 作者给一句话大纲
2. AI 扩写成 3-5 段

```
👤 张三推开石门，发现里面是师父的尸体。

🤖 AI 扩写为 3-5 段：

石门很重，我用尽了全身的力气才推开。
一股陈腐的气息扑面而来，我下意识地退了一步。

借着火折子的微光，我看到了地上的身影。
是师父。
我的师父。

他的眼睛睁着，似乎在看着我。
但他已经没有了呼吸。

【总共 5 段，250 字】
```

### 3.3 模式 C：润色模式

**流程**：
1. 作者写一段粗糙的草稿
2. AI 提供润色版本

```
👤 我走进山洞。山洞很黑。我很害怕。但是我必须进去。

🤖 AI 润色：

我缓步踏入山洞，四周的黑暗如同实质般压来。
恐惧在心底悄然蔓延，但我的脚步没有停下——

【保留你的核心意思 + 美化文风】
```

### 3.4 模式 D：建议模式

**流程**：
1. 作者卡在某段
2. AI 提供 3 个走向建议

```
👤 我不知道接下来该怎么写...

🤖 AI 给 3 个走向建议：

【建议 1：情感爆发】
张三扑到师父身边，发现师父手里握着一封信...

【建议 2：悬疑深入】
张三仔细观察，发现师父身边有一只怪物的爪印...

【建议 3：战斗开场】
突然，山洞深处传来怪物的吼声，张三立刻进入战斗状态...

你想哪个？或者自己写？
```

## 四、完整流程

### 4.1 第 1 步：确定协作模式

```
🤖 AI: 共写模式！你写一段，我来接。

选择协作方式：

A. 接续模式（我接 3 个版本给你选）
B. 扩写模式（你给大纲，我扩写）
C. 润色模式（你写草稿，我润色）
D. 建议模式（卡住了，我给建议）

输入 A/B/C/D ✍️
```

### 4.2 第 2 步：开始协作

**接续模式示例**：

```
👤 [作者写第 1 段]

🤖 [AI 分析上下文 + 生成 3 版本]

👤 [作者选择]

🤖 [继续生成下一段]

[循环]
```

### 4.3 第 3 步：保存与归档

```
🤖 AI: 我注意到你刚才写了 5 段（约 800 字）。

要不要保存到项目里？
A. 保存到第 X 章
B. 仅作为草稿
C. 继续写（暂不保存）
```

## 五、AI 接续的 3 个版本设计

### 5.1 版本类型

每次接续生成 3 个版本：

| 版本 | 特点 | 适用 |
|------|------|------|
| **版本 A：稳妥** | 平铺直叙，稳扎稳打 | 大多数情况 |
| **版本 B：悬疑** | 加点悬念，吸引读者 | 想要张力 |
| **版本 C：动作** | 加点动作，推进剧情 | 想要爽感 |

### 5.2 3 版本示例

**接续点**：张三推开石门

```
【版本 A：稳妥】
门后是一间宽敞的石室。火把的光芒在墙壁上跳跃，
照亮了地上的几具尸骨。

【版本 B：悬疑】
门后是一片漆黑。但我听到了——微弱的呼吸声。
有人在这里。还活着。

【版本 C：动作】
门后陡然冲出一只怪物！它张开血盆大口，
我侧身躲过，剑光一闪——
```

### 5.3 版本选择的灵活性

```
用户: "我想要 A 的开头，但 B 的结尾"
   ↓
AI: "明白了，我结合两个版本的元素写新版本..."

[生成混合版本]
```

## 六、上下文感知

### 6.1 7 层上下文（简化版）

每次接续前，AI 自动加载：

| 层 | 内容 | 用途 |
|----|------|------|
| Layer 1 | 主角当前状态 | 保持状态一致 |
| Layer 2 | 最近 3 章正文 | 保持风格一致 |
| Layer 3 | 当前场景 | 保持场景一致 |
| Layer 4 | 已埋的伏笔 | 适时回收 |
| Layer 5 | 用户文风样本 | 保持文风一致 |

### 6.2 一致性保障

**自动检查**：
- 主角实力不能突增
- 已发生事件不能矛盾
- 资源使用要合理
- 角色语气要一致

**如果用户输入与已有设定冲突**：

```
🤖 AI: ⚠️ 我注意到你说「张三有 200 灵石」，
       但他在第 5 章只有 150 灵石。

你想：
A. 改成 150 灵石（保持一致）
B. 加 50 灵石（需要合理剧情）
C. 忽略警告（继续）

输入 A/B/C ✍️
```

## 七、特殊场景

### 7.1 用户不知道写什么

```
👤 我不知道写什么...

🤖 AI: 没关系，我给你几个选择：

【选择 1：场景型】
"一个安静的夜晚，张三坐在窗前..."
（你续写或选我续）

【选择 2：动作型】
"张三的剑已出鞘，对手站在对面..."
（你续写或选我续）

【选择 3：情感型】
"张三看着手中的信，眼眶湿润了..."
（你续写或选我续）

输入 1/2/3 或自己开头 ✍️
```

### 7.2 用户写了不满意

```
👤 [用户选择继续]
       ↓
👤 "算了，不满意，我重新写"

🤖 AI: 好的，删除上一段。
       回到上一段的开头，你重新写。
```

### 7.3 用户突然要 AI 自动写

```
👤 "算了，你帮我写完整章节吧"

🤖 AI: 好的，切换到 /novel:continue 模式...
```

## 八、与其他协议的协同

### 8.1 cowrite → continue

```
用户想 AI 自动写完整章节：
   ↓
调用 protocol.entry_routing 入口 2
```

### 8.2 cowrite → fix

```
用户对 AI 写的部分不满意：
   ↓
调用 protocol.quality_scoring 检测
   ↓
调用 protocol.entry_routing 入口 3（fix）
```

### 8.3 cowrite → save

```
用户完成一段后想保存：
   ↓
保存到当前章节
   ↓
更新事实锁 + 章节进度
```

## 十、性能要求

- **响应时间**：≤ 10 秒（生成 3 个版本）
- **每个版本**：1-3 句（接续模式）或 3-5 段（扩写模式）
- **上下文加载**：≤ 30K tokens

## 十一、错误处理

### 11.1 用户输入太短

```
🤔 你只写了「嗯」。
   
   你想表达什么？能多说一点吗？
   或者我帮你扩写？
```

### 11.2 用户输入太长

```
😊 你写了一段长文（800 字）。

要不要：
A. 直接进入润色模式（我帮你优化）
B. 拆分保存为多个段落
C. 作为完整章节保存
```

### 11.3 上下文冲突

```
⚠️ 我注意到你说「张三」，
   但你之前写的是「李四」。

你想：
A. 我把「李四」改成「张三」（统一）
B. 这是两个角色（我标记为不同角色）
C. 我错了，我重新说
```

## 十二、与其他 skill 的差异

相比其他 skill 的"协作模式"：
- tianming：没有协作模式
- MyNovel：自动生成，不支持协作
- webnovel：自动生成，不支持协作

**本协议创新**：**"作者主导 + AI 接续"**——保留创作控制权，AI 仅作为"加速器"。
