# 章节目录协议（Table of Contents Protocol）

[REF:protocol.toc]

## 一、设计哲学

**核心原则**：**"章节目录 = 大纲的执行清单"**

章节目录把大纲（3 层）落地为具体的章节列表——每章都有标题、核心事件、目标字数。

**为什么需要章节目录？**
- 写作者每天打开文档，知道今天写哪一章
- 防止"重复剧情"或"跳剧情"
- 便于读者追更（标题即钩子）

**核心策略**：
- ✅ **每章都有强钩子标题**（不是"第 12 章"）
- ✅ **每章 1-3 个核心事件**
- ✅ **支持分批生成**（先 30 章 → 续写时再 30 章）
- ✅ **自动适应大纲修改**

## 二、章节目录的粒度

### 2.1 卷级目录（推荐先做）

```yaml
第 1 卷：入门崛起（第 1-100 章）
   卷核心：张三能否在宗门立足？
   卷高潮：第 100 章 身世揭秘
```

### 2.2 50 章级目录（推荐批次做）

```yaml
第 1-50 章：宗门入门篇
   第 1-10 章：入门篇
   第 11-25 章：外门立足篇
   第 26-50 章：内门冲刺篇
```

### 2.3 单章详细目录（核心）

```yaml
第 12 章：大比初战
   标题类型：悬念型
   核心事件：张三用透视符箓看穿对手，进入 16 强
   目标字数：3500 字
   钩子：王二警告张三"有人要对付你"
```

## 三、生成流程

### 3.1 第 1 步：输入参数

```yaml
input:
  outline: <book_outline + volume_outline>
  chapters_per_batch: 30
  start_chapter: 1
```

### 3.2 第 2 步：生成 30 章详细目录

```python
def generate_chapter_toc(outline, chapters_per_batch):
    chapters = []

    for i in range(chapters_per_batch):
        chapter = {
            'number': outline.start_chapter + i,
            'title': generate_title(outline, i),
            'core_event': extract_core_event(outline, i),
            'emotion': assign_emotion(outline, i),
            'target_words': calculate_words(outline),
            'hook': generate_hook(outline, i),
            'foreshadow': link_foreshadows(outline, i)
        }
        chapters.append(chapter)

    return chapters
```

### 3.3 第 3 步：用户审阅 + 修改

```
📚 第 1 卷前 30 章目录（草稿）

【第 1-10 章：入门篇】
第 1 章   入门测试
第 2 章   破格录取
第 3 章   外门杂役
...

你想：
A. 接受，继续生成第 31-60 章
B. 修改某些章节（告诉我）
C. 调整标题风格（更热血/更悬疑）
```

## 四、章节标题设计（5 大类型）

### 4.1 悬念型（推荐）

**公式**：`[事件] + [未解之谜]`

**示例**：
- 第 1 章 入门测试（悬念：为什么破格录取？）
- 第 8 章 师姐失踪（悬念：谁下的手？）
- 第 30 章 神秘来信（悬念：谁写的？）

**适用**：悬疑向、剧情向

### 4.2 战斗型

**公式**：`[角色] + [动作] + [对手/目标]`

**示例**：
- 第 5 章 张三首战
- 第 12 章 大比初战
- 第 100 章 决战光明顶

**适用**：爽文、战斗向

### 4.3 转折型

**公式**：`[原状态] + [转折词] + [新状态]`

**示例**：
- 第 8 章 从此再无张三
- 第 50 章 天才的陨落
- 第 100 章 我不是张三

**适用**：剧情有重大转折的章节

### 4.4 揭秘型

**公式**：`[真相/秘密]`

**示例**：
- 第 30 章 师父的真实身份
- 第 75 章 透视符箓的来历
- 第 95 章 师姐的真正目的

**适用**：回收伏笔的章节

### 4.5 情感型

**公式**：`[情感] + [对象/事件]`

**示例**：
- 第 15 章 师徒重逢
- 第 45 章 那一夜
- 第 80 章 永远的告别

**适用**：情感向、虐心向

### 4.6 混合型（实战推荐）

**示例**：
- 第 12 章 大比初战·透视显威（战斗 + 揭秘）
- 第 30 章 师父真相·身世初显（揭秘 + 转折）
- 第 100 章 飞升之夜·天道永存（情感 + 转折）

## 五、章节信息完整性

### 5.1 完整章节信息

```yaml
chapter:
  number: 12
  title: 大比初战·透视显威

  # 类型与节奏
  type: 战斗                  # 战斗/转折/揭秘/情感/混合
  pace: 中等                  # 快速/中等/舒缓

  # 核心事件
  core_events:
    - "张三首次使用透视符箓看穿对手破绽"
    - "张三进入宗门大比 16 强"

  # 情绪曲线
  emotion_curve:
    - 紧张 (前 1/3)
    - 燃点 (中 1/3)
    - 期待 (后 1/3)

  # 章末钩
  ending_hook:
    type: 悬念                  # 悬念/战斗/揭秘/反转
    content: "王二警告张三'有人要对付你'"

  # 目标字数
  target_words: 3500

  # 关联伏笔
  foreshadows:
    plant:                       # 本章埋设的伏笔
      - id: FS-013
        content: "神秘老者给了张三一枚符箓"
    reveal:                      # 本章回收的伏笔
      - id: FS-005
        chapter: 8
        content: "师姐提到的'大比诅咒'"

  # 关联事实锁
  fact_locks:
    - id: FL-XXX
      description: "张三进入 16 强"

  # 关联角色
  characters:
    focus: [张三, 对手（赵无极）]
    supporting: [王二, 主考官]

  # 关联地点
  locations:
    - 青云宗比武场
```

### 5.2 最小必要信息（快写模式）

```yaml
chapter_minimal:
  number: 12
  title: 大比初战
  core_event: "张三进入 16 强"
  target_words: 3500
```

## 六、分批生成策略

### 6.1 为什么分批？

- 长篇目录不可能一次性生成 500 章
- 分批生成 = 用户审阅 + 调整的机会
- 写作时才知道哪些章节需要详细

### 6.2 推荐分批

| 批次 | 章节数 | 用途 |
|------|--------|------|
| 第 1 批 | 30 章 | 详细目录（含核心事件 + 情绪曲线 + 钩子） |
| 第 2 批 | 30 章 | 详细目录（基于前 30 章调整） |
| 第 3 批 | 30 章 | 占位目录（仅标题 + 核心事件） |
| 第 4+ 批 | 占位 | 仅标题（"待续"） |

### 6.3 分批示例

```
第 1 批：第 1-30 章（详细）
   ↓ 用户审阅
   ↓ 调整（如有）
第 2 批：第 31-60 章（详细）
   ↓ 用户审阅
   ↓ 调整（如有）
第 3 批：第 61-100 章（占位）
第 4 批：第 101+ 章（待续）
```

## 七、目录修改与追溯

### 7.1 修改章节标题

```
用户: "把第 12 章标题改成更悬疑的"
   ↓
AI: 好的，给你 3 个选项：
  - "大比初战·阴影浮现"
  - "比武场的陌生人"
  - "王二的警告"
   ↓
用户选 1
   ↓
更新 + 标题自动同步到事实锁
```

### 7.2 调整章节顺序

```
用户: "把第 50 章移到第 30 章"
   ↓
AI: 这个调整会影响：
  - 第 31-49 章的逻辑
  - 第 51+ 章的衔接
   ↓
AI: 自动生成过渡章节，确保衔接自然
```

### 7.3 删除章节

```
用户: "删掉第 25 章"
   ↓
AI: 警告！这会影响：
  - 第 24 章 → 第 26 章的衔接
  - 第 25 章埋设的伏笔 FS-013

你想：
A. 强制删除（需要调整其他章节）
B. 合并到相邻章节
C. 暂存为草稿
```

## 八、章节目录的存储

### 8.1 文件结构

```
你的小说项目/
├── toc/
│ ├── chapter_001.md   ← 详细章节信息
│ ├── chapter_002.md
```

## 九、与其他协议的协同

### 9.1 toc → write

```
章节目录生成完成：
   ↓
用户开始写
   ↓
调用 protocol.write（基于当前章节目录）
```

### 9.2 toc → stuck

```
写某章时卡住：
   ↓
调用 protocol.stuck_rescue
   ↓
参考章节目录 + 上下文生成 3 方向
```

### 9.3 toc → fact_lock

```
每章生成完成：
   ↓
调用 protocol.fact_lock
   ↓
基于章节目录生成事实锁
```

## 十、错误处理

### 10.1 章节标题雷同

```
⚠️ 我发现你的章节标题有重复：
  - 第 5 章 "大比初战"
  - 第 15 章 "大比再战"
  - 第 25 章 "大比终战"

虽然这是有意为之（系列感），但可能让读者疲劳。

建议：
- 改变部分标题
- 或加副标题区分

继续？
```

### 10.2 章节钩子弱

```
⚠️ 第 50 章的钩子偏弱："张三继续修炼"
建议改为：
- "张三的修为突然停滞"
- "师父深夜来访"
- "一个改变命运的请求"

想换吗？
```

## 十二、与其他 skill 的差异

相比其他 skill 的"目录"：
- tianming：用 markdown 列表，无详细字段
- MyNovel：固定 50 章一批，无差异化设计
- webnovel：分散在多个 references/

**本协议创新**：**"5 大标题类型 + 分批生成 + 修改追溯"**——专业网文编辑方法论。
