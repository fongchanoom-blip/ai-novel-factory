# 快速试写协议（Quick Write Mode）

[REF:protocol.quick_write]

## 一、设计哲学

**核心原则**：**"1 分钟内让用户看到 AI 按 TA 的想法写出来"**

demo 让用户看到 AI 能写什么，quick 让用户看到 AI 能按 **用户的想法** 写什么。

**为什么需要 quick？**
- demo 是 AI 主导，quick 是用户主导
- 用户更关心"AI 能不能按我的思路写"
- 1 分钟体验 = 立即确认 Auto-Novel 是否适合自己

**核心策略**：
- ✅ **接收用户的一句话灵感**
- ✅ **生成 3 个不同方向**（每个 800 字）
- ✅ **让用户选择**最喜欢的方向
- ✅ **不创建项目**（仅试写）
- ✅ **不要求知识库**（用通用默认）

## 三、完整流程

### 3.1 第 1 步：接收并解析灵感（5 秒）

```yaml
输入示例：
  "/novel:quick 玄幻废柴少年，金手指是透视符箓"

自动解析：
  题材: 玄幻
  主角特征: 废柴少年
  金手指: 透视符箓
  补充信息: 无
```

### 3.2 第 2 步：生成 3 个方向（20 秒）

**3 个方向的设计原则**：

| 方向 | 描述 | 适用用户 |
|------|------|----------|
| **方向 A：稳妥版** | 按网文经典套路写 | 大多数用户 |
| **方向 B：创新版** | 加点反套路元素 | 喜欢新鲜的 |
| **方向 C：情感版** | 强化情感线 | 重视情感的 |

每个方向 800 字，包含：
- 开篇场景
- 主角亮相
- 第一个冲突
- 章节钩子

### 3.3 第 3 步：3 选 1（用户决策）

```
📖 我按你的「玄幻废柴少年，金手指是透视符箓」生成了 3 个方向：

【方向 A：稳妥版】（传统废柴逆袭）
张三，乙等下品灵根，意外获得透视符箓。在宗门入门考核中，
他决定隐藏实力，等待关键时刻...
（800 字完整片段）

【方向 B：创新版】（废柴反套路）
张三被检测出"无灵根"，却被神秘宗门破格录取。原来所谓的
"无灵根"是万年一遇的"天灵根"...
（800 字完整片段）

【方向 C：情感版】（师徒情深）
张三从小被师父养大，师父临终前给他一张符箓："这是透视符箓，
为师此生最后一件礼物。找到那个害我的人..."
（800 字完整片段）

你最喜欢哪个方向？

A. 稳妥版 → 我按这个写完整第 1 章（3500 字）
B. 创新版 → 我按这个写完整第 1 章
C. 情感版 → 我按这个写完整第 1 章
D. 都不喜欢 → 我重新生成 3 个方向
E. 混合 A 和 B → 我结合两个方向的元素

输入 A/B/C/D/E ✍️
```

### 3.4 第 4 步：展开完整第 1 章（可选）

```
用户选 A/B/C/E 后：

AI: 好的，我按「[选中的方向]」展开完整第 1 章（3500 字）...

（30-40 秒后）

📖 第一章 入门测试

[完整 3500 字正文]

【5 维评分】
- 人设一致性：9.3
- 世界观一致性：9.5
- 逻辑性：9.0
- 文风一致性：8.8（⚠️ 建议微调）
- 非重复性：9.4
- 总评：9.20 ✅ 通过

💡 继续？
A. /novel:new → 正式开始这部小说
B. /novel:quick 其他灵感 → 再试一个
C. /novel:fix aidetect → 先去 AI 味

输入你想做的 ✍️
```

## 四、3 个方向的具体设计

### 4.1 方向 A：稳妥版（传统套路）

**特征**：
- 主角设定符合经典套路
- 金手指使用清晰
- 剧情推进平稳
- 适合大部分读者

**示例**：
- 玄幻废柴少年 → 乙等下品灵根 → 意外获得透视符箓 → 宗门入门考核隐藏实力 → 关键时刻爆发
- 都市职场新人 → 普通毕业生 → 获得"先知"金手指 → 商战中预判对手 → 一战成名

### 4.2 方向 B：创新版（反套路）

**特征**：
- 加 1-2 个反套路元素
- 剧情有意外转折
- 适合喜欢新鲜的读者

**示例**：
- 玄幻废柴 → 被检测出"无灵根" → 但被神秘宗门录取 → 原来"无灵根"是"天灵根"
- 都市金手指 → 主角预知能力 → 但每次预知都要付出代价（生命/记忆/情感）

### 4.3 方向 C：情感版（情感线）

**特征**：
- 强化情感描写
- 加入师徒/亲情/友情线
- 适合重视情感的读者

**示例**：
- 玄幻 → 师父被反派害死 → 临终赠透视符箓 → 主角为师父报仇
- 都市 → 主角失忆 → 女友不离不弃 → 金手指与失忆前的自己有关

## 五、输入处理

### 5.1 接受的输入格式

```bash
# 标准格式
/novel:quick "玄幻废柴少年，金手指是透视符箓"

/novel:quick 玄幻废柴少年          # 无引号也可

/novel:quick                        # 不指定，自动询问
```

### 5.2 自动询问（如果用户没指定）

```
🤖 AI: 让我快速问你几个问题（每个回答 5 秒）：

❓ 什么题材？
  1. 玄幻/仙侠  2. 都市/现代  3. 言情  4. 悬疑
  5. 科幻  6. 历史  7. 其他（告诉我）

❓ 主角是什么人？
  1. 废柴少年  2. 强者归来  3. 普通人觉醒  4. 大佬重生
  5. 已有想法（告诉我）

❓ 金手指/特殊能力？
  1. 透视符箓  2. 系统流  3. 重生/穿越  4. 血脉觉醒
  5. 暂无  6. 已有想法（告诉我）

输入数字或描述 ✍️
```

## 六、输出规范

### 6.1 试稿字数

```
3 个方向：每个 800 字（±100）
完整第 1 章：3500 字（±200）
```

### 6.2 文风统一

**所有方向必须用统一的文风**（避免 demo 与 quick 文风不一致）：
- 默认：古风仙侠 / 半文半白
- 都市：现代网感 + 适度口语
- 言情：细腻情感 + 优美词句

### 6.3 章节钩子

每个方向都必须有**强钩子**：
- 悬念型："原来这就是她十年来一直隐藏的真相"
- 反转型："这一刻，他终于明白了师父临终那句话的含义"
- 战斗型："下一章，他将面对真正的对手"

## 七、与 demo 的区别

| 维度 | demo | quick |
|------|------|-------|
| 用户输入 | 无 | 必填灵感 |
| 输出 | 1 个固定试稿 | 3 个不同方向 |
| 目标 | 展示 AI 能力 | 展示 AI 按用户想法 |
| 时间 | 30 秒 | 60 秒 |
| 文风 | 固定（玄幻） | 根据题材适配 |

## 八、错误处理

### 8.1 灵感太模糊

```
🤔 你说的「玄幻」我有点不太明白。

让我猜一下你想要什么：

1. 经典修仙（升级打怪）
2. 都市修仙（现代修真）
3. 仙侠言情（情感为主）
4. 仙侠悬疑（阴谋揭秘）

或者直接告诉我更多细节？
```

### 8.2 灵感太复杂

```
😊 你的灵感很丰富！但我想先聚焦一个核心：

你最重要的 1 个元素是什么？
（如：废柴少年、透视符箓、宗门大比）

其他的我会在后续章节里加入。
```

### 8.3 生成失败

```
😅 抱歉，AI 这会儿没灵感，让我重新试试...

（10 秒后重试）
```

## 十、与其他协议的协同

### 10.1 quick → new

```
用户选了方向 + 选了"正式开始"：
   ↓
调用 protocol.entry_routing
   ↓
进入新建小说的 9 步流程
   ↓
用户选的方向作为初始设定
```

### 10.2 quick → fix

```
用户觉得"AI 味重"：
   ↓
调用 protocol.quality_scoring + novel:fix aidetect
   ↓
针对选定章节去 AI 化
```
